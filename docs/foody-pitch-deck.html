Judging · Technological Implementation
How it works · architecture

A small, deterministic agent over Socket Mode.

Trigger & intent
Phrase matchers in intent.ts — “let's eat”, “order”, “change address to …”. A list, not a model.
↓
Session state
addr_<user> sticky address book · sess_<chan>_<thread> live cart.
↓
Discovery
Restaurant & dish lookup near the address, cached with a 24h disk TTL + daily prewarm.
↓
Pre-reacted menu
Top 10 dishes posted as one Block Kit message Foody pre-reacts to.
↻
Reconcile from reactions
Cart = the actual reactions on the message (reactions.get) — self-healing.
↓
Order → checkout → receipt
Builds the real basket in your Cloudflare-cleared Chrome; receipt lands in-thread.
Why this design wins
✓
The interface is just emoji. Group ordering with zero new UI — reactions on a message.
✓
Reconcile, don't accumulate. A dropped Slack event never desyncs the cart.
✓
Private by default. Outbound WebSocket (Socket Mode) — no public URL, nothing leaves the workspace.
✓
Deterministic core. No LLM in the request path — fast, predictable, debuggable.
Judging · Quality of the Idea
What makes it hard — and original

The simple feeling hides real engineering.

🪄

The interface is just emoji

Group ordering with zero new UI: reactions on a message are the whole input device. Everyone already knows how to tap one.

🩹

A self-healing basket

Socket Mode never replays missed events, so we reconcile the cart from the message's real reactions. Even on a flaky network it converges to the truth.

⚙️

Deterministic, not a chatbot

No LLM in the runtime path — intent is a list of phrase matchers, so a given input always does exactly the same thing. Fast, predictable, debuggable.

🛒

A real checkout

Not a mock receipt: Foody drives an actual takeaway.com basket in your signed-in, Cloudflare-cleared Chrome — ready to confirm.

Judging · Potential Impact
Impact & what's next

Every team with a Slack and a lunch break.

Who it's for

  • Every Slack team — the moment is universal and recurring, daily.
  • Beyond lunch: the pattern (propose → react → converge → act) fits any group decision in Slack.
  • Provider-agnostic: the same emoji interface can front any delivery service behind one adapter.

What's next

  • Bill splitting — automatic per-person totals posted to the thread.
  • Recurring lunches — “every Friday at 12:00, ask the channel.”
  • Smarter consensus — quick polls, dietary filters, budget caps.
  • Optional AI concierge — “surprise us under €12,” kept out of the deterministic core.
